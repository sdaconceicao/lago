# Public token reference

This page defines Lago's supported CSS custom properties and their override
scope. Start with [Setup](?path=/docs/design-tokens-setup--docs) for imports,
theming, and cascade layers. The
[Overrides example](?path=/story/design-tokens-overrides--default) demonstrates
the difference between inherited theme values and component overrides.

## Support and scope

  <thead>
    <tr>

    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Global theme tokens</td>
      <td><code>:root</code>; use <code>:root.dark-mode</code> for theme-specific values</td>
      <td>Shared values and palette definitions listed below</td>
    </tr>
    <tr>
      <td>Optional inherited inputs</td>
      <td>A component or ancestor, unless a variant declares the same property locally</td>
      <td>A <code>var()</code> fallback supplies the default when the input is absent</td>
    </tr>
    <tr>
      <td>Local appearance overrides</td>
      <td>The element that owns the treatment, in unlayered consumer CSS</td>
      <td>Can replace that element&#x27;s local defaults and state choices</td>
    </tr>
    <tr>
      <td>Field metrics</td>
      <td>The relevant supported <code>[data-field-size]</code> element</td>
      <td>Derived metrics are reset at every supported size boundary</td>
    </tr>
    <tr>
      <td>Private properties</td>
      <td>Do not set them</td>
      <td>Implementation details without a compatibility guarantee</td>
    </tr>
  </tbody>
</table>

Inheritance and cascade priority are different. An inherited property loses to
a declaration on the element itself, even when the ancestor's rule is unlayered.
An unlayered declaration on the **same element** outranks Lago's normal layered
rules, including variant, hover, disabled, and forced-color rules. Choose the
scope first, then handle the affected states deliberately.

Only properties listed here are public. A name without an underscore is not,
by itself, a promise that a property is a supported customization input.

## Global theme tokens

Use semantic colors for their named roles. Palette steps and hue seeds are
available for intentional custom treatments. Review foreground/background
contrast and interaction states when changing a palette or semantic color.

Derived values resolve where they are declared. Set `--tint`, `--gray`, and
palette construction inputs on `:root`, where their palettes are defined.
Changing only `--tint` on a subtree does not regenerate the palette inherited
from `:root`. For a component hue override, use its documented input instead.

```css
:root {
  --tint: oklch(0.7 0.15 250);
  --font-family: "Inter", system-ui, sans-serif;
  --radius: 10px;
}
```

Font sizes, spacing, and radii accept CSS lengths. At `min-resolution: 200dpi`,
Lago changes the default spacing to `0.3125rem` and the three font sizes to
`0.9375rem`, `1.0625rem`, and `1.25rem`. The tables below describe ordinary
resolution defaults, not fixed dimensions at every display density or root
font size. Radius defaults remain pixel lengths.

Every supported `data-field-size` boundary (`sm`, `md`, or `lg`) redeclares
these metrics. A custom root
`--field-height` does not replace a sized field's local height. Apply advanced
overrides to the sized element and preserve both layout invariants:

- `--field-padding-x` equals twice `--field-inner-inset`.
- `--field-inner-height` plus twice `--field-inner-inset` equals both
  `--field-height` and `--field-reserved-inline-end`.

```css
/* Apply this class to the actual sized field element. */
.dense-field[data-field-size="md"] {
  --field-height: calc(8 * var(--spacing));
  --field-inner-height: var(--spacing-5);
  --field-inner-inset: calc(1.5 * var(--spacing));
  --field-padding-x: var(--spacing-3);
  --field-reserved-inline-end: calc(
    var(--field-inner-height) + 2 * var(--field-inner-inset)
  );
}
```

A portaled popover does not inherit a field wrapper's custom properties. Lago
carries the selected size to its associated popovers; custom metric rules
must also reach the popover's sized element if the menu should match.

## Shared treatment inputs

These inputs apply to the element using the button, indicator, or inset
appearance. They are not a promise that every component using that appearance
exposes the same DOM structure. Prefer public props for size, variant, state,
and selection before overriding CSS.

### Buttons

    </tr>
    <tr>
      <td><code>--button-gradient</code>, <code>--button-highlight</code>, <code>--button-text</code></td>
      <td>Local appearance colors; vary by theme, variant, and state</td>
    </tr>
  </tbody>
</table>

The first five inputs above use private fallback aliases. The remaining
appearance properties have direct local declarations. In particular, the
root `--button-background` semantic token and the local button property share
a name: a Button's local background wins over the inherited root value.
Set the property on the Button itself to override it. Root
`--button-background-pressed` is used by other button-like surfaces and does
not replace Button's local hover/pressed treatment.

```css
/* Assign className="brand-button" to the Button. */
@media (forced-colors: none) {
  .brand-button:not([data-disabled]) {
    --button-color: var(--purple);
  }
}
```

This preserves Lago's disabled and forced-color treatments. A direct local
background/text override can also outrank hover or selected styling; specify
the intended state treatment instead of expecting inheritance to restore it.

For component appearance overrides, use the same disabled-state exclusions

## Private properties and runtime measurements

Properties beginning with `--_` are private resolved aliases. Other unlisted
properties are also private, including derived `--feedback-*` outputs other
than `--feedback-color`, Alert's `--alert-*` aliases, component sizing
intermediates, `--fill-*`, `--origin`, and `--editor-rows`. Read the corresponding
component prop rather than relying on these implementation values.

React Aria measurements and runtime values are not Lago token inputs:
`--page-width`, `--page-height`, `--visual-viewport-height`, `--trigger-width`,
`--disclosure-panel-height`, `--tab-panel-height`, `--tab-panel-width`,
`--table-row-level`, `--tree-item-level`, and `--percent`. Do not overwrite them
to re-theme a component.

## Compatibility and deprecation

The supported name, accepted value type, semantic role, and documented scope
of a public token are compatibility commitments. Palette and appearance values
can evolve while preserving those roles; consumers should verify custom
foreground/background pairs and states when updating Lago.

A public-token replacement must include a CHANGELOG entry, its replacement,
and a migration example. Keep an alias or equivalent compatibility fallback
for at least one published minor release before removal. Changing a public
name, value type, role, or supported scope is a breaking change: use a breaking
minor release while Lago is below 1.0, or a major release from 1.0 onward.
Patch releases must not silently retract these contracts. Private properties
and React Aria runtime measurements do not receive this token guarantee.
