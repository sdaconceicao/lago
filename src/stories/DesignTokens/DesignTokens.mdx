# Design Tokens

Lago exposes CSS custom properties for global theming and component styling.
This page covers how to consume and customize them. The **Colors**, **Text**,
and **Spacing** stories show the **live** values for the current theme — toggle
the **Theme** toolbar (Light / Dark) to see how they change. It starts on
whichever your OS prefers. The [public token reference](?path=/docs/design-tokens-reference--docs)
lists supported names, defaults, override scopes, and the deprecation policy.
The [override examples](?path=/story/design-tokens-overrides--default) demonstrate
inheritance and component-scoped customization.

## Using Lago tokens in a consuming app

Lago ships a single stylesheet with global tokens on `:root`, a
`:root.dark-mode` block for dark values, field metrics on `[data-field-size]`,
and component-local appearance properties. Theming is driven entirely by the `dark-mode` class on `<html>`, which
`ThemeProvider` toggles based on the selected theme (system, light, or dark).

### 1. Import the stylesheet

Import the compiled tokens/components CSS once at your app's entry point:

```ts
import { ThemeProvider } from "@code-x/lago";
import "@code-x/lago/styles";
```

### 2. Wrap your app

Wrap your tree in `ThemeProvider`. By default it follows the OS preference
(`defaultTheme="system"`). Pass `defaultTheme="light"` or `"dark"` to force a
theme, or call `setTheme` / use `useTheme()` at runtime.

```tsx
<ThemeProvider defaultTheme="system">
  <App />
</ThemeProvider>
```

### 3. Customize the tokens

Override global tokens on `:root` with your own CSS. Derived palettes resolve
where their declarations live: changing a seed such as `--tint` on `body` or a
subtree does not recalculate an inherited `--tint-100` value. Component inputs
and field metrics have their own scopes; see the reference before overriding them.

- **Rebrand:** set `--tint` to your brand color — the entire
  `--tint-100 … --tint-1600` scale is derived from it automatically.
- **Neutrals:** override `--gray`, or the `--lightness-*` / `--chroma-*` ramps,
  to reshape the gray scale.
- **Semantic colors:** override individual tokens such as `--text-color`,
  `--border-color`, `--field-background`, or `--highlight-background` directly.
- **Typeface:** Lago ships an `--font-family` token that defaults to Open Sans
  (with a native `system-ui` fallback stack) — override `--font-family` on your
  `:root` or `body` for styled controls (see the **Text** story). Plain `Heading`
  and `Text` inherit typography from the consuming document.

```css
:root {
  --tint: oklch(0.7 0.15 250); /* your brand color */
  --font-family: "Inter", system-ui, sans-serif; /* your typeface */
}

/* Preserve Lago's semantic system-color mappings in forced-color mode. */
@media (forced-colors: none) {
  :root {
    --background-color: #fafafa;
    --text-color: oklch(30% 0 0);
  }

  :root.dark-mode {
    --background-color: #121212;
    --text-color: oklch(95% 0 0);
  }
}
```

### 4. Dark mode

Leave `defaultTheme="system"` to follow the OS, or force it. Dark values live
under `:root.dark-mode`, so override that selector (not `prefers-color-scheme`)
to customize them.

### 5. Use tokens in your own components

Reference tokens directly in your CSS for a consistent look:

```css
.my-card {
  background: var(--field-background);
  border: 1px solid var(--border-color);
  border-radius: var(--radius);
  padding: var(--spacing-4);
  color: var(--text-color);
}
```

### 6. Cascade layers, and restyling a component

Everything Lago ships is emitted into cascade layers, declared in this order:

```css
@layer reset, lago.tokens, lago.base, lago.components;
```

`tokens` holds the custom properties, `base` the shared treatments components
are built from, and `components` the per-component rules — lowest priority
first, so each layer can build on the one before it. If you have met Tailwind's
`theme, base, components` this is the same arrangement.

#### Put your CSS reset in the `reset` layer

`reset` is declared first, and Lago never writes into it. It is there for your global reset styles. This is important because unlayered author CSS has higher priority than all normal layered author CSS, regardless of specificity. An unlayered reset can therefore unexpectedly override Lago's component styles.

```css
/* Unlayered — and so it beats every rule Lago has, at any specificity.
   Every component silently loses its padding: buttons collapse to the
   width of their label. */
* {
  padding: 0;
  margin: 0;
}

/* Layered into the slot Lago reserves — still resets the browser's defaults,
   no longer outranks Lago. */
@layer reset {
  * {
    padding: 0;
    margin: 0;
  }
}
```

Because the slot is declared in Lago's own stylesheet, this works wherever your
reset sits in the import order.

Unlayered consumer styles beat normal layered declarations on the **same element**, however
specific the layered rule is — layer order is resolved *before* specificity. So
a single class selector of yours overrides any Lago rule, and re-theming is
never a specificity fight:

```css
/* wins, even though Lago's own rule is more specific */
.react-aria-Button {
  border-radius: 0;
}
```

Layer priority compares declarations on the same element. An inherited value
from `:root` or a wrapper does not compete with a declaration made directly on
a child. For example, root `--button-background` is a palette value used by
controls such as RangeCalendar, while buttons resolve their own local
`--button-background` from their hue, variant, and state.

Three things follow from that.

**Choose the supported scope.** Optional inputs such as `--button-color` and
`--button-icon-size` use `var()` fallbacks and can inherit unless a component or
state supplies a local value. Appearance properties such as
`--button-background`, `--indicator-border`, and `--inset-border` have local
defaults: set them on the actual button, indicator, or inset surface. A CSS class
on a TextField wrapper does not directly target its input or grouped surface.
The reference distinguishes these categories instead of treating every custom
property as an inherited input.

```css
/* A class passed to Button changes its hue while retaining state treatments. */
@media (forced-colors: none) {
  .my-button:not([data-disabled]) {
    --button-color: var(--purple);
  }
}
```

**Keep state and system-color behavior deliberate.** Unlayered overrides also
outrank matching state rules. Exclude disabled controls, and limit visual
rebranding to `forced-colors: none` so system colors remain effective. A direct
appearance override replaces that property's hover/pressed treatment too;
supply state-specific values when the design needs them.

```css
@media (forced-colors: none) {
  /* Explicitly target the component, rather than declaring these on :root. */
  .react-aria-Button[data-variant="primary"]:not([data-disabled]) {
    --button-background: var(--tint);
    --button-border: oklch(from var(--tint) 50% c h);
    --button-gradient: var(--button-border);
    --button-highlight: rgb(255 255 255 / 0.2);
    --button-shadow: oklch(from var(--tint) 30% c h);
    --button-text: var(--highlight-foreground);
  }
}
```

**Don't reach for `!important`.** It *reverses* layer order — an `!important`
declaration inside a layer beats an `!important` one outside it — so against a
Lago rule it can make things worse. Being unlayered is already enough.
